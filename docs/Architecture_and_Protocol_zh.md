# 模型架构与实验方案

## 当前实现

输入句子经过启发式检测后按需改写，再依次经过 BART 编码器、规范化后的 Mamba 处理、特征融合和 BART 解码器，最后由作者审阅建议。

检测器匹配口语化或模糊表达，输出位置与原因。它是演示原型，不能测量学术风格准确率。后续需要独立标注 revise/keep 样本并训练监督检测器。不能将所有修改前句子标为“风格差”、所有目标句标为“理想风格”，再将这些弱标签当成评价真值。

设 Transformer 编码结果为 H，M = Mamba(LayerNorm(H))，支持以下融合。

- residual 残差：Z = H + M。
- gated 门控：G = sigmoid(W[H; M] + b)，Z = H + G ⊙ M。
- replace 替换：Z = M，用于消融跳连。

解码器通过交叉注意力读取 Z，在训练时使用教师强制预测目标 token。目标是忽略填充位置的 token 交叉熵。推理采用相同编码与融合路径，再自回归解码。右侧填充使因果 Mamba 有效位置不受后续填充影响。适配模块单向处理，因为 Transformer 状态已包含双向源句上下文。Hybrid 仍有注意力，不能据此称整个模型为线性复杂度。

ReferenceMamba 采用 Mamba-1 基本结构：输入投影与门控、因果逐通道卷积、输入相关的 delta/B/C、负对角矩阵 A、离散状态递推、D 跳连与输出投影。这是教学用途的 PyTorch 顺序实现，未验证与官方内核的数值一致性或 GPU 效率。官方后端显式导入 mamba_ssm，缺失时会报错。

已有 30 步实验使用随机小型 BART：隐藏维度 64、一层编码器和一层解码器、两个注意力头、前馈维度 128、仅在训练集学习的按词词表。种子为 42，批量为 4，长度为 128。两次实验在加适配模块前建立相同主干初始权重，处理相同的 64 对训练记录，按相同种子抽取批次；验证使用 16 对。参数量不同，因此它们是流程检查，尚非严格研究对比。

## 下一阶段正式实验

1. 扩充并人工审核学术修订对，独立标注学术语气和语义。核查事实、数字、否定、限定词和引用，评审者不知模型身份。
2. 用全部训练样本微调 facebook/bart-base，只用验证集选择超参数和检查点，补充早停与最佳模型保存。现有固定步数训练器是扩展起点。
3. 加入适配模块，先冻结主干训练新增层，再选择性解冻。在 Linux/WSL2 验证官方 Mamba，记录准确内核与包版本，检查数值和梯度。
4. 对比 Transformer-only 与 Hybrid，统一划分、预训练主干、token 长度、解码、更新或数据预算，采用种子 [13, 42, 2026]。报告参数量与预算。增加参数量相近的 Transformer 对照，区分额外容量与结构影响。
5. 保持其他条件一致，运行 residual/gated/replace 消融。时间和资源允许时开发条件式 Mamba-only 生成器，披露预训练差异，避免把影响全部归为结构。
6. 冻结方案后评估保留测试集，报告跨种子均值与变化范围，按模型和检查点编号归档预测。不能根据测试样本调参。

## 评价方案

- 检测：独立标注下的精确率、召回率和 F1；规则命中率不是风格准确率。
- 参考重合度：SacreBLEU 与 ROUGE-L，记录版本、分词和参考处理。现有空白分词 ROUGE-L 是诊断值，不能与其他分词的论文分数混用。
- 语义：固定编码器版本的 BERTScore，并结合对事实、数字、否定、限定词和引用的盲评；这些措施不能单独保证语义等价。
- 学术语气：独立人工评分或保留数据上的监督分类器，不能用被评价模型自身生成的标签判定。
- 效率：相同长度和批量下，记录参数量、预热且 CUDA 同步后的延迟中位数和 p95、训练时间与峰值已分配显存。现有单次小模型记录不是优化后基准。

建议用 30–50 个保留样本、两名评审，按 1–5 分评价学术语气、流畅度和语义，并另记事实变化。样本量按时间确定，报告一致性与分歧。期望改善学术语气且无不可接受的语义退化，目前尚未设判定阈值或证明达标。
