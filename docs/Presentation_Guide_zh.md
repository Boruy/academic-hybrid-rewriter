# 第二次汇报讲稿与问答

中英文 PPT 均为 7 页，建议 6–7 分钟。以下讲稿适用于中文版页面，也可配合英文版汇报。中文版文件与全部说明见 [中文材料总目录](Chinese_Materials_Index_zh.md)。

## 第 1 页

我们研究学术文本的风格增强，目标是在保留事实和原意的前提下，帮助作者发现并改写不合适的表达。第一阶段提出 Transformer 与 Mamba 混合结构，本次重点展示已经落实的数据、代码与运行证据。我们的范围仍然是英文句子级修订，作者保留最终决定权。今天展示的小模型是流程验证，尚不具备实际改写质量。
来源：本地 Proposal.pdf；数据与代码证据见 README.md、docs/Progress_Evidence.md。

## 第 2 页

我们正式选用了作者发布的 IteraTeR-HUMAN sentence 数据，而不是规模更大的 FULL 或 v2。下载版本固定并记录了哈希。原始数据共四千零十八对，包含多个领域。我们根据 arXiv 文档编号筛选学术文本，保留 style、clarity 和 fluency，删除空文本、重复、过长样本以及数值变化的文本对，得到六百七十六对。按文档分组重新划分，训练四百九十一、验证九十八、测试八十七对。这是按文档组划分八比一比一，所以句子数量比例不会完全一致。跨集合的文档和完全相同文本重叠都是零。下面的例子来自上游人工修订，不能当成模型输出。也需要强调，标签并不等于一定改善了学术风格。
来源：https://huggingface.co/datasets/wanyu/IteraTeR_human_sent ；https://github.com/vipulraheja/iterater ；data/raw/manifest.json；data/processed/stats.json。示例：arXiv 2012.08987，上游 train.json 第 778 行。

## 第 3 页

模型首先用 Transformer 编码源句，获得包含全句上下文的表示。Mamba 参考模块对表示做选择性状态空间处理，再通过残差或门控融合送给 Transformer 解码器。默认门控公式是 Z 等于 H 加上 G 乘 M，训练目标是忽略 padding 的序列交叉熵。我们实现了 gated、residual 和 replace 三种融合方式，其中 replace 用来消融跳连。当前 Mamba 使用普通 PyTorch 顺序扫描，是用于验证的参考实现，尚未验证与官方优化内核的数值一致性。它依然保留 Transformer 注意力，因此不能声称整个模型已经实现线性复杂度或速度提升。
来源：src/academic_rewriter/models.py；https://arxiv.org/abs/2312.00752 ；https://github.com/state-spaces/mamba 。

## 第 4 页

目前完成了清洗、文档级划分、仅用训练集学习的 tokenizer、动态 padding、目标掩码，以及两个模型的训练和生成流程。我们使用同一随机种子和小型 BART，在六十四个真实训练样本上分别运行三十步，验证集使用十六对。表中给出相同固定训练批次的前后损失，验证交叉熵则来自独立验证子集。两个模型都完成了反向传播、生成和保存。四项测试覆盖了数据泄漏、数值保护、Mamba 梯度和三种融合路径。这里的损失变化只说明流程已打通，不能说明 Hybrid 更好。保存的验证样例生成结果为空，无法用于改写，测试集没有参与模型评估。
来源：runs/transformer_smoke/result.json；runs/hybrid_smoke/result.json；runs/tests.txt。

## 第 5 页

当前最明显的问题是监督信号与项目目标之间还有差距。六百七十六对数据里只有二十四对标为 style，绝大多数属于清晰度和流畅度修订，因此我们需要扩充数据并独立标注学术风格。其次，数值一致检查只能发现部分事实变化，否定、语气、实体和引用还要人工检查。技术上，官方 Mamba 对运行环境和内核有要求，本机当前验证的是顺序扫描参考模块，不能用来推导优化版本的效率。另外，检测器仍然是规则原型，预训练微调、Mamba-only 基线和正式质量评估都未完成。
来源：data/processed/stats.json；src/academic_rewriter/detect.py；https://github.com/state-spaces/mamba 。

## 常见问答

**为什么选 IteraTeR？** 它包含可追溯的真实修订与编辑意图，且包含 arXiv 文本。我们使用 HUMAN sentence 版本做小规模学术修订试验，不把通用领域或全部编辑直接当成学术风格监督。

**为什么只有 676 对？** 我们限定 arXiv 文档与三种编辑意图，并加入长度、重复和数值变化过滤。详细丢弃原因与数量保存在 stats.json。这个规模用于验证流程，主实验需要扩充并人工审核。

**为什么不是精确的 80/10/10 句子数？** 我们按连接文档组分配 76/9/10 组，避免同一论文或完全相同文本泄漏，不按句子随机切分。

**Mamba 的作用是什么？** 作为编码表示上的选择性状态空间适配模块，检验它是否能补充 Transformer 表示。有效性仍是假设，需要与 Transformer Baseline 及融合消融进行比较。

**已经证明 Hybrid 更好吗？** 没有。30 步随机小模型只检查数据与梯度、训练和生成是否连通。微小损失差异不能支持质量优势，当前模型输出不可用于学术写作。

**已经完成官方 Mamba 集成吗？** 没有。当前是 PyTorch 参考递推，可运行并有梯度检查；官方 mamba_ssm 是可选接口，尚未完成环境和数值一致性验证。

**模型会更快吗？** 现在不能下结论。本次参考扫描在该运行中比 Transformer 慢，完整 Hybrid 仍保留注意力。必须使用相同长度和批量，在验证过的优化后端上测量延迟、显存和参数量。

**如何评估保留原意？** 自动指标与人工盲评结合，重点核查数字、否定、限定词、实体和引用。BERTScore 与数字检查都不能单独保证语义等价。

**为什么先不实现 Mamba-only？** 本阶段优先保证核心 Transformer 与 Hybrid 路线可复现。Mamba-only 需要条件生成建模且预训练条件可能不同，保留为后续对照，报告中明确尚未完成。

**仓库在哪里？** 当前交付为本地仓库，可查看 README、src、tests 与 runs。远程 GitHub 尚未创建，不能在幻灯片中填一个不存在的链接。

**老师要求必须有完整训练结果吗？** 根据提供给我们的要求，Milestone 需要数据、模型、进展、问题和计划，未明确要求最终训练完成。提交前仍应以老师的课程大纲原文为准。
